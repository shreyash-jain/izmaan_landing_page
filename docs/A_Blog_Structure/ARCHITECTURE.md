# ARCHITECTURE — Izmaan Lodge

How the site is built, the exact commands, the image pipeline, and the traps. Verified
against the repo on 2026-08-21.

---

## Stack

Next.js **14.2.5** (App Router) · React · TypeScript · Tailwind (with `autoprefixer`) ·
**static export** (`output: "export"`, `images.unoptimized: true`) · deployed to
**Cloudflare Pages**.

**Posts are Markdown**, not components: `content/blog/*.md` with YAML frontmatter, read by
`lib/posts.ts` through `gray-matter`. Adding a post is dropping in a `.md` file — no route
to scaffold, no registry to hand-edit.

```
content/blog/<slug>.md
        │
        ├── lib/posts.ts (node:fs + gray-matter)   ──►  /journal, /journal/<slug>
        │
        └── scripts/gen-registry.mjs               ──►  lib/posts-registry.generated.ts
                                                         (dependency-free, committed,
                                                          read by the analytics Function)
        ▼
  next build (output: export)  ──►  out/
        ▼
  scripts/to-dist.mjs          ──►  dist/     ──►  Cloudflare Pages
```

`to-dist.mjs` renames `out/` to `dist/` because Cloudflare Pages looks for a `dist`
output directory by default — so no dashboard configuration is needed.

## Commands

| What | Command |
|---|---|
| Install | `npm install` |
| Dev server | `npm run dev` |
| **The build that matters** | `npm run build` — `gen-registry` → `next build` → `to-dist` |
| Regenerate the registry only | `npm run gen:registry` |
| Serve the built site | `npm start` (`scripts/serve.mjs`) |
| Cloudflare preview | `npm run preview:admin` (`wrangler pages dev dist`) |
| Lint | `npm run lint` |

## Key modules

| Path | Responsibility |
|---|---|
| `content/blog/<slug>.md` | A post — frontmatter + body. The whole post |
| `lib/posts.ts` | Reads the folder with `node:fs` + `gray-matter`. Types: `PostMeta`, `Post`, `Faq` |
| `lib/posts-registry.generated.ts` | Baked, dependency-free copy for the Cloudflare Function. **Committed** |
| `scripts/gen-registry.mjs` | Emits the above; runs inside `npm run build` |
| `app/journal/[slug]/page.tsx` | Renders a post **and emits the `FAQPage` JSON-LD** — the real structured-data asset |
| `lib/site.ts` | Brand, contact, geo, booking — the single source of truth |
| `lib/images.ts` | Image slots |
| `public/images/blog/` | Post images |
| `public/images/lodge/` | The owners' real property photos — **never AI-generate these** |

## Generating blog images (OpenRouter)

Blog images are generated by the session itself — the marketing lead never saves,
downloads or renames a file. **Exactly three per post** (1 cover + 2 in-body), and
**never the property itself** — see [CLIENT.md](CLIENT.md). Append each post's three
prompts to [`AI-IMAGE-PROMPTS.md`](../../AI-IMAGE-PROMPTS.md), whose shared style spec
should be appended to every prompt.

**The key lives outside every repo**, at:

```
C:\Users\Admin\.blog-keys.env
```

`C:\Aadi` is itself a git repository, so nothing secret may live under it. Never copy the
key into a repo, never print it, never paste it into chat. The file holds
`OPENROUTER_API_KEY` and `OPENROUTER_IMAGE_MODEL`.

Write a **throwaway** script into the session scratchpad — never into this repo — holding
this post's prompts. The API contract:

```js
// scratchpad/gen-images.mjs  —  run with: node scratchpad/gen-images.mjs
import { readFileSync, writeFileSync } from "node:fs";

const env = Object.fromEntries(
  readFileSync("C:/Users/Admin/.blog-keys.env", "utf8")
    .split(/\r?\n/)
    .filter((l) => l.trim() && !l.trimStart().startsWith("#") && l.includes("="))
    .map((l) => [l.slice(0, l.indexOf("=")).trim(), l.slice(l.indexOf("=") + 1).trim()])
);

const jobs = [
  { file: "public/images/blog/<slug>.jpg",        prompt: "…16:9… <style spec>" },
  { file: "public/images/blog/<slug>-reef.jpg",   prompt: "…" },
  { file: "public/images/blog/<slug>-gear.jpg",   prompt: "…" },
];

for (const { file, prompt } of jobs) {
  const res = await fetch("https://openrouter.ai/api/v1/chat/completions", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${env.OPENROUTER_API_KEY}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      model: env.OPENROUTER_IMAGE_MODEL,
      messages: [{ role: "user", content: prompt }],
      modalities: ["image", "text"],
    }),
  });
  const json = await res.json();
  if (!res.ok) throw new Error(JSON.stringify(json).slice(0, 800));
  const url = json.choices?.[0]?.message?.images?.[0]?.image_url?.url;
  if (!url) throw new Error("no image in response: " + JSON.stringify(json).slice(0, 800));
  writeFileSync(file, Buffer.from(url.split(",")[1], "base64"));
  console.log("wrote", file);
}
```

> **If the API response shape differs from the above, fix this file.** It is the repo's
> memory of the contract — correcting it once saves every future session the rediscovery.

**Verified working 2026-08-21.** The recipe above ran unchanged against
`google/gemini-3-pro-image` (~25 s per image) and `google/gemini-3.1-flash-image`
(~18 s), both returning `choices[0].message.images[0].image_url.url` as a
`data:image/png;base64,...` URL. Output was 16:9 and honoured the "no people, no
text, no logos" constraints. **`qwen/qwen-image-3` does not exist on OpenRouter** —
there are no Qwen image models there, and it fails with `404 No endpoints found that
support the requested output modalities`. If a model id is ever rejected, list the
valid ones with `GET https://openrouter.ai/api/v1/models` and filter on
`architecture.output_modalities` containing `image`.

**Verify every generated image before showing it:** open it and look at it, confirm no two
are byte-identical, confirm the aspect ratio, and confirm none of them depicts the lodge,
a room, the kitchen or a bathroom.

## Traps

**The generated registry goes stale.** `lib/posts-registry.generated.ts` is committed, so
a deploy that skips the prebuild still works — but if you add a post and don't rebuild,
the analytics endpoint labels the new page with nothing. `npm run build` regenerates it;
make sure the regenerated file lands in your commit.

**`keywords:` frontmatter is decorative.** It only emits meta keywords, which nothing
reads. The `faq:` block is what matters — it becomes `FAQPage` JSON-LD.

**`output: "export"` means no server.** No API routes, no server-side image optimisation
(`images.unoptimized: true` is required). Pre-size source images.

**Cloudflare expects `dist/`.** `to-dist.mjs` renames `out/` after the build. If a build
appears to produce nothing deployable, check that step ran.

**`postcss.config.mjs` malware.** A recurring obfuscated build-time payload across these
repos, hidden behind hundreds of spaces so it renders as a blank line in editors and
diffs. **Clean here = 9 lines / 157 bytes / longest line 51 chars** (this repo's config is
the object form with `tailwindcss` + `autoprefixer`). Detect by line length, never by eye:

```bash
awk '{print length}' postcss.config.mjs | sort -n | tail -1     # expect ≤ 60
```

If anything on the remote looks tampered with — a payload on `main`, a forged merge
commit, a force-push — **stop and escalate. Do not attempt a cleanup from a blog
session.** The remediation playbook is
`.saral/docs/PLAYBOOK-force-push-worm-future-sessions.md` in the krazy-kreators repo, and
it is a technical-owner job.
